## 2. 새 자료의 방식

신규 36편은 시 전문과 외부 현대어 번역을 싣지 않은 **교재 병행형**이다. 〈지수정가〉는 특히 작품개관에 근거한 보충 학습이며, EBS의 정확한 비교 지문을 직접 판독했다고 하지 않는다. 기존 37편의 본문 또는 발췌문은 그대로 유지한다.

새 작품마다 자체 작성한 핵심 판단 8개(적절한 이해·오독·판단 이유)를 넣었다. 이를 공통 문항 구성기로 이해 유도 8문항 → 핵심 정리 → 일반 3문항 → 적용 3문항 → 종합 5문항으로 반복 확장한다. 따라서 **36×19=684문항**은 단계별 질문 인스턴스의 수이며, 서로 무관한 684개 독립 문항을 모두 개별 출제·검토했다는 뜻이 아니다. 반복 학습과 개념 적용이 목적이다.

종합 실전은 180문항이며 선택지별 판단 근거 900개가 생성된다. 비교 자료는 기존 작품에 대한 자체 작성 독해 관점이지 시 원문·번역문이 아니다. 화면에서 ‘원문 아님’을 표시한다. 신규 문항에는 `practiceBasis: authored-concept`를 사용하며, 기출 대조·실측 수능 난도로 오인시키지 않도록 기존 자료와 달리 ‘적용 연습’·‘종합 실전’으로 표시한다.

## 3. 구현 및 보존

새 진입점은 `korean-library.html`, 새 학습 경로는 `korean-reader.html?lesson=<id>`다. 전체 목록은 제목·작가 검색, 갈래, 주요/보충, 본문 포함/교재 병행/개관별 선택을 지원한다. 기존 화면의 길게 펼쳐진 작품 메뉴는 전체 목록으로 가는 링크로 정리했다. 모든 기존 작품의 직접 URL은 유지한다.

신규 저장 키는 `study-poetry-<id>-v1`, 콘텐츠 버전은 `<id>-20261018-v1`이다. 기존 키를 삭제하거나 바꾸지 않는다. 정답 위치는 질문 ID에 따라 결정적으로 섞어 새로고침 후에도 같은 선택지 순서를 유지한다. 잘못된 ID·누락 데이터에는 오류 안내와 목록 링크를 제공한다.

공통 렌더러는 명시적인 `data-lesson-mode="textbook"`에서만 새 안내와 단계명을 사용한다. 기존 모드의 채점·저장·초기화 코드는 유지한다. 공통 CSS와 기존 37편 데이터, 수학 자료는 변경하지 않는다. 기존 Pages 산출물 234개 중 공유 파일 3개만 변경했으며 나머지 **231개는 바이트가 같다**. 이 수에는 생성된 문서 HTML 등도 포함되어 있으므로 231개 독립 기능이라는 뜻은 아니다.

서비스 워커는 v56→v57 및 신규 43개 URL만 추가했다. 기존 186개 CORE URL과 순서를 보존하여 총229개가 된다. 기존 수학 업로드 쿼리 URL도 유지한다. 실제 네트워크 수명 주기는 이번에 검사하지 않았다.

## 5. 2026-10-19 실제 적용 검증

2026-10-18에는 추가 패키지만 준비했으나, 2026-10-19 사용자 지시에 따라 실제 저장소 반영을 진행한다. GitHub에서 main이 기준 커밋과 같은 것을 다시 확인했다. 기준 커밋의 성공한 Pages 산출물을 기준본으로 사용하고 패키지 manifest의 기존 파일·새 파일 해시를 대조했다. 컨테이너의 직접 Git 복제는 DNS 조회 실패로 실행되지 않아, 적용 파일만 준비한 뒤 GitHub Git 데이터 API로 새 트리와 커밋을 구성하는 방식을 사용한다. 로컬 Git 저장소에 설치기를 실행했다고 주장하지 않는다.

적용 시 정적 검사와 Chromium 검사를 다시 실행하여 위 4절의 수치와 같은 결과를 얻었다. 기존 산출물 231개 보존, 신규 36편 전 단계 진행·684문항 구성·900개 종합 근거, 기존 공통 렌더러 36편의 실전 채점을 다시 확인했다. 새로 생성한 모바일 전체 목록과 데스크톱 학습 화면도 직접 열어 시각 검수했다. 코드 10개 파일은 준비한 패키지와 동일하며 본 문서만 실제 적용 기록으로 갱신한다. 실제 HTTP 탐색은 다시 차단되어 영속 저장소와 오프라인 동작의 검증 한계는 그대로다.

GitHub에는 위 11개 경로만 반영한다. 테스트 코드·대역·스크린샷·설치기·로컬 백업은 게시하지 않는다. 병합 전 변경 경로를 대조하고 Pages의 빌드·배포 결과를 별도로 확인한다. 다음 설치기 설명은 기존 배포 패키지의 기능 설명이며 이번 원격 반영에 설치기를 사용했다는 뜻은 아니다.

패키지의 `apply_update.py`는 기본적으로 검사만 한다. `--apply`를 주어도 파일만 적용하며 커밋·푸시는 하지 않는다. 기준 커밋·기존 파일 해시·패키지 해시·깨끗한 작업 트리·경로/심볼릭 링크를 확인한 뒤 적용한다. 불일치는 강제로 덮어쓰지 않고 중지한다. 원본 백업을 Git 관리 디렉터리 안에 남기며, 적용 중 실패하면 이 작업이 쓴 파일을 복원한다. 개별 파일 교체는 원자적이지만 시스템 전원 단절까지 포함한 전체 저장소 트랜잭션을 보장하는 방식은 아니다.

설치기 자체의 실행 결과는 패키지 `validation/qa-installer.json`에 별도로 기록한다. 원격 배포 성공 기록이 아니다.
